# Test Results Directory

This directory contains organized test output files generated by the enhanced TypeScript test runner with comprehensive output management.

## Directory Structure

The enhanced test runner creates timestamped subdirectories for each test run:

```
test-results/
├── run_2025-06-14T19-58-21/          # Timestamped test run directory
│   ├── metadata.json                  # Run metadata (timestamp, options, environment)
│   ├── summary.json                   # Test summary with counts and results
│   ├── complete-output.log            # Full Jest output (ANSI-stripped)
│   ├── backend_backend_tests_integration_auth.api.test.ts.log  # Individual suite outputs
│   ├── backend_backend_tests_unit_services_token.service.test.ts.log
│   └── ...                           # One file per test suite
├── run_2025-06-14T20-01-47/          # Another test run
├── README.md                          # This documentation
└── .last-run.json                    # Last run status (tracked)
```

## Enhanced Test Runner Features

### 🚀 **TypeScript-Powered Execution**

- Uses `tsx` for direct TypeScript execution
- Full ES module compatibility
- Type-safe test runner implementation

### 📁 **Organized Output Management**

- **Separate files per test suite** - No more massive single files
- **Timestamped directories** - Easy chronological organization
- **ANSI-stripped logs** - Clean, readable output files
- **Descriptive filenames** - Path-based naming for easy identification

### 🔄 **Automatic Log Rotation**

- Keeps only the 10 most recent test runs
- Prevents disk space accumulation
- Configurable retention policy

### 📊 **Accurate Result Tracking**

- Real-time progress indicators (✅❌⏭️)
- Jest summary parsing for precise counts
- Comprehensive metadata tracking

## Usage Examples

### NPM Scripts (Recommended)

```bash
# Run all tests with enhanced output
npm test

# Run specific project tests
npm run test:backend
npm run test:frontend
npm run test:ai-server
npm run test:collaboration-server
npm run test:packages

# Run with options
npm run test:coverage      # Generate coverage reports
npm run test:watch         # Run in watch mode
npm run test:verbose       # Verbose output
```

### Direct Usage

```bash
# Basic usage
npx tsx scripts/run-tests-with-output.ts [target] [options]

# Examples with patterns and comments
npx tsx scripts/run-tests-with-output.ts --pattern "auth" --comment "Testing auth system"
npx tsx scripts/run-tests-with-output.ts frontend --pattern "Button" --comment "UI component tests"
npx tsx scripts/run-tests-with-output.ts backend --coverage --comment "Backend coverage check"
```

## File Contents

### metadata.json

Contains run information:

- Timestamp and duration
- Target project and pattern
- Comments and environment details
- Node.js version and platform

### summary.json

Contains test results summary:

- Pass/fail/skip counts
- Exit code and duration
- List of generated log files

### Individual Suite Logs

Each test file gets its own log with:

- Test suite header with timestamp
- Complete test output (ANSI-stripped)
- All console output and stack traces

## Git Integration

- **Tracked files**: `README.md`, `.last-run.json`
- **Ignored files**: All `run_*/` directories with test outputs
- **Log rotation**: Old runs automatically cleaned up (last 10 kept)

This ensures test results don't bloat the repository while preserving configuration and documentation.

- `npm run test:watch` - Run tests in watch mode (console only, no file output)

### Direct Script Usage

```bash
# Basic usage
node scripts/run-tests-with-output.js [test-type]

# With issue tracking
node scripts/run-tests-with-output.js --comment "Issue description" [test-type]

# Examples
node scripts/run-tests-with-output.js backend
node scripts/run-tests-with-output.js --comment "Fixing auth bug" backend
node scripts/run-tests-with-output.js -c "Testing new feature" frontend
```

## Cleanup

Old test result files should be cleaned up periodically to save disk space. Consider keeping only the most recent results or important milestone test runs.

## Git Ignore

Test result files (`*.txt`) in this directory are automatically ignored by Git to prevent cluttering the repository with test output logs. Only the README.md file is tracked.
